# FC Arena Goldfish release review

The five stages used fresh reviewer contexts with the installed EGM 0.1.1 package. Review addressed the [release design](fc-arena-release-design.md) and its linked startup and operator references. The Linux web artifact was built from `4a9aab2d9f7485cc4d8f3cee727ceb5657b4b188`. The live baseline at review was `2b50f0ae358d1c9ffca306fc800a1dcd2876bbd4` for the web and API.

## Review findings and dispositions

1. **Initial Zoom Out.** Preserve the native Activity boundary, establish source parity before locking the candidate, and retain the runnable rollback pair. The revised plan compares source and active builds separately, stages web independently, and retains the current API.
2. **Comprehension.** The reviewer could explain the startup handoff and release order. The revised plan names the Android state transitions, the systemd services and operator actions, backup isolation, and health-triggered recovery.
3. **Critic Review.** The design, structure, and style reviews asked for alternatives, a problem statement, compatible cross-version behavior, precise backup evidence, bounded restore resources, and an Android readiness measure distinct from Activity draw. The feature description and detailed plan address these points. Backup ciphertext and signed-device evidence remain operational checks.
4. **Intermediate Zoom Out.** The review found encryption was being conflated with the daily local dump. It also asked for a live-compatible test pairing and a runnable rollback. The design separates the storage audit from the requested production criteria of backup integrity and isolated restore. It distinguishes staged builds from public Play binaries and requires a web-only rehearsal with an independently checked API marker.
5. **Implementation Readiness.** Reviewers independently identified two blockers. The first was the absence of an executable web switch and reverse procedure. It was addressed by running the baseline, candidate, and baseline again through the same loopback systemd service with staged work and environment paths. The second was treating published Android binaries as runnable in the fixture harness. The harness uses debug-only WebView inspection, so the design now specifies baseline and candidate debug builds for isolated startup and contract coverage, and the installed Play build and physical-device acceptance separately for distribution. The review also required exact source reconciliation, named CI checks, the backup migration ledger, and the clean-main signing and track checks. The release design records those requirements.

## Operational evidence

- The web candidate passed all 14 GitHub checks, including Android API 33–36, frontend, backend, security, and the source-release gate. The Playwright web suite passed 12 cases and Home passed 11 additional regression scenarios. Real isolated staging verified sign-in, next match, Cup search, saved opponent WhatsApp privacy, and pending-result reset against the API revision used by production.
- The runtime source comparison found no material divergence across the examined live web files. The release does not change API runtime sources or migrations. Live-only API test files and the active checkout are preserved. Live migration metadata matched the 48 baseline migrations by name and checksum after normalizing line endings where necessary.
- The Linux artifact was checksum-verified on VCCLHosting, expanded in its own directory, and exercised on a loopback-only service. The previous web, candidate web, and previous web each returned the expected release marker, login and dashboard, and all 20 referenced dashboard chunks. The public web and API retained their original process IDs during the rehearsal. The retained API release was healthy throughout.
- The scheduled local archive verified and restored with 46 applied migrations. It preceded the two newest live migrations. A new root-only snapshot was captured and restored in a network-disabled PostgreSQL 17 container with a 384 MiB memory cap and 192 MiB data tmpfs. It passed the SHA-256 check and contained 64 tables, 48 applied migrations and zero unresolved migrations. Both archives stayed on the authorized host.
- On 16 November 2026 IST the public web switched to `4a9aab2d9f7485cc4d8f3cee727ceb5657b4b188`. The release marker, login, dashboard, and all referenced dashboard JS/CSS passed. Direct and same-origin API health reported the retained `2b50f0ae358d1c9ffca306fc800a1dcd2876bbd4` release with database and Redis connected. The independent repository availability probe and [GitHub production web verification](https://github.com/keerthiprakash18/FC-ARENA-/actions/runs/43750756950) both passed.
- The installed backup service retains raw local dumps. The repository supports encrypted off-server retention. This host showed no configured backup encryption recipient or encrypted archive. Recoverability of off-server ciphertext remains unverified.
- Play Console showed code 21 / 1.0.19 as the highest uploaded bundle and active on the Production track. The public Play upload certificate matched the existing signing helper. Code 22 / 1.0.20 was built as an unsigned AAB with release lint and 32 native unit tests passing. The upload-key holder must unlock the local signing key for the signed AAB. Play distribution remains pending signing and installed-device acceptance.
